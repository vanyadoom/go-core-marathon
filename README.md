# 🚀 Интенсивный марафон по Go Core (Путь к Junior Go Developer 2027)

Добро пожаловать в мой личный репозиторий ежедневного практического марафона по бэкенд-разработке. Этот проект служит детальным инженерным журналом моего пути в освоении языка **Go (Golang)**, архитектуры программного обеспечения и фундаментальных основ Computer Science.

Мой жёсткий дедлайн для полного прохождения этого трека и выхода на уровень готового к коммерческой продакшн-разработке Junior-инженера — **31 декабря 2026 года**.

## 🛠️ Технологический стек и освоенные навыки

*   **Язык программирования:** Go (Golang) Core, статическая типизация, явное приведение типов, области видимости переменных.
*   **Управление памятью:** Механика размещения данных (Стек против Кучи), семантика указателей, мутация состояния объектов, ловушки копирования значений, архитектура слайсов (длина `len` против вместимости `cap`).
*   **Структуры данных:** Линейные списки (динамические слайсы и append), ассоциативные хэш-таблицы (карта `map` с мгновенным поиском за $O(1)$ и случайным порядком итерации), слайсы структур (таблицы объектов).
*   **Объектно-ориентированный Go:** Инкапсуляция данных через структуры, фабричные функции-конструкторы с валидацией бизнес-логики, привязка поведения через методы (получатели указателей `Pointer Receiver` против получателей значений `Value Receiver`), композиция объектов вместо наследования (встраивание структур со скрытым подъёмом полей `Field Promotion`).
*   **Контрактная архитектура:** Проектирование поведения через интерфейсы, утиная типизация (неявная реализация интерфейсов), полиморфные слайсы интерфейсов, динамическая диспетчеризация во время выполнения (работа таблиц методов `itab`).
*   **Продвинутый бэкенд:** Строгая явная обработка ошибок, работа с динамическими типами (`interface{}` / `any`), безопасное извлечение типов (`Type Assertion` с идиомой `comma ok`), множественная маршрутизация типов (`Type Switches` с оптимизацией через таблицы переходов `Jump Table`).
*   **Инструменты разработки:** Уверенная работа с Git через терминал (интерактивная подготовка файлов, контроль статуса, визуализация графа коммитов), продвинутое использование Visual Studio Code (горячие клавиши форматирования и рефакторинга кода).

## 🗺️ Дорожная карта марафона и выполненные шаги

### 📦 Блок 1: Базовый синтаксис Go и управление потоком
*   **Шаги 1–6:** Переменные, резервирование памяти, условные ветвления (`if/else`), сложные логические фильтры (`&&`, `||`), короткое замыкание вычислений, правила явного приведения типов и калькуляторы налогов.
*   **Шаги 7–10:** Управление циклами (`for`), операторы прерывания итераций (`break`, `continue`), генерация двумерных координатных сеток и изолированные функции на уровне пакета с множественным возвратом значений.

### 📦 Блок 2: Коллекции данных и управление памятью
*   **Шаги 11–15:** Фиксированные массивы против динамических слайсов, расширение скрытых массивов через `append`, масштабирование данных «на месте» (In-place), многомерные динамические матрицы и фиксированное форматирование вывода таблиц через `Printf`.
*   **Шаги 16–20:** Инициализация хэш-таблиц через `make`, безопасный поиск элементов через идиому `comma ok`, удаление ключей за $O(1)$ через `delete()`, ловушка рандомизации циклов по картам, проектирование кастомных структур и извлечение свойств объектов в общих накопителях.

### 📦 Блок 3: Объектная модель Go и привязка поведения
*   **Шаги 21–22:** Внедрение методов через получатели, изоляция временных копий данных против изменения оригинального состояния объекта в памяти с помощью указателей (`*`), отслеживание размещения объектов в Стеке и Куче.
*   **Шаги 23–25:** Кастомная строковая сериализация через встроенный интерфейс `Stringer` (`fmt.Sprintf`), функции-фабрики (конструкторы) с автоматической валидацией входящих данных, композиция структур вместо наследования с прямым доступом к памяти.

### 📦 Блок 4: Интерфейсные контракты и полиморфизм
*   **Шаги 26–27:** Объявление интерфейсов, неявная реализация контрактов, полиморфные списки интерфейсов и глубокий разбор динамической диспетчеризации времени выполнения (`itab`).
*   **Шаги 28–30:** Работа с универсальными коробками неизвестных данных (`interface{}` / `any`), разбор системной структуры `eface` в ядре Go, защита компилятора от паники через безопасное приведение типов (`Type Assertion`), множественный выбор типов через конструкцию `Type Switch` с аппаратной оптимизацией процессора.

### 📦 Блок 5: Продакшн-операции бэкенда и работа с системой (Текущий блок)
*   **Шаг 31 (Последняя победа):** Реализация монолитной явной обработки ошибок, разбор встроенного интерфейса `error`, проверки на `nil` и микрооптимизация работы условий на уровне блоков предсказания переходов (`Branch Prediction`) процессора.
